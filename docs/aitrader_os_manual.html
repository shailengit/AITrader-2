aitrader_os

A voice-first control plane for the AITrader-2 quantitative trading repo: Alpaca paper telemetry into Postgres, Strategy Lab batches on demand, evolution notes in your Obsidian vault, and a hard confirmation gate in front of anything that changes state.

4 tools 3 bot profiles Postgres + Obsidian wake word: “hey hermes”

01 · What this is

Hermes is the agent; aitrader_os is the bridge to your trading stack. It has exactly four jobs, and every one of them is a tool the model can call from a normal sentence — typed or spoken:

Pull the numbers

Account equity, open positions, every order fill with limit-order slippage, and 90-day Sharpe / drawdown / return land in dedicated os_* Postgres tables.

Run the experiments

Backtest batches go through your own Strategy Lab API, so results appear in the same experiment table, Coach library and report viewer as a UI batch.

Remember what you learned

Reflections and parameter mutations become Markdown notes with a before/after diff table, indexed in Postgres and searchable in Obsidian forever.

Operate the repo

Tests, lint, git status, data updates, migrations — an allowlist of named commands, never free-form shell.

Design rule. The plugin writes only to its own os_* tables. Your journal_*, strategy_* and 1,500 per-ticker tables are read-only to it — a bug here can never corrupt market data.

04 · Using your voice

Everything below works spoken or typed. Saying “Hey Hermes” opens a fresh voice session; the reply is spoken back in the current profile's voice.

Wake

“Hey Hermes” — on-device, no audio leaves the Mac. Works in the main chat and in every Bot Chat; the bot whose window is focused owns the mic.

Barge in

Start talking mid-reply and playback stops; your new sentence wins.

Stop

Say “stop” on its own to end the voice session without asking the agent.

Say the phrase with a few words of intent — “Hey Hermes, what's my equity” — rather than the two words alone. The bundled model needs a couple of frames of speech to be certain, and a bare phrase is marginal on a cold detector.

Speak like this, not like a form

Voice turns are short. Every tool result carries a spoken field — one or two clean sentences — so the agent has something safe to read out instead of a table.

Give me the twenty-second version.Cuts a long analysis to the headline plus one caveat.
Skip the table, just tell me the number that matters.Any result with a spoken field answers this directly.
Read me the account summary.Uses sync_alpaca_telemetry action metrics: equity, day P&L, Sharpe, drawdown.
Voice safety. Anything that changes state asks out loud first: “This dispatches 40 backtest runs… should I start it?” Only a clear yes executes it. A mumble, a maybe or a changed request re-arms the question.

sync_alpaca_telemetry

Pulls Alpaca paper performance into Postgres, and reads it back.

run_strategy_backtest

Dispatches batches through your own backend (POST /api/strategy-lab/sessions/_/experiments with a strategy_class_path) — no LLM session needed, results in the same tables as the UI.

actionUse it for

The 20-run rule. At confirm_above_runs: 20 and above, the tool refuses to dispatch until you confirm out loud. A 100-run batch is roughly 40 minutes of CPU — the guard exists so it never starts by accident.

08 · Workflow recipes

Recipe A — the 16:20 close ritual

The cron job already does this on weekdays at 16:20. Run it by hand any time:

bash ~/.hermes/scripts/aitrader_daily_loop.sh

It syncs the three accounts, computes Sharpe/drawdown/expectancy, writes Daily/<date> - Daily review.md, and flags anything with negative expectancy. A cron turn then has @quant-dev analyse each flagged strategy and append a reflection — proposals only, never a mutation.

Recipe B — a controlled mutation, start to finish

  1. Establish the baseline. “Run 10 windows on daily_golden_cross ending last Friday.”
  2. Change one parameter, on a branch, and log it:
    Log a mutation on DailyGoldenCrossRotation: ema_fast from 10 to 20, because win rate fell to 44% over the last 76 trades.Creates the vault note with the diff before you run anything — the intent is recorded even if the result is bad.
  3. Re-run with the same windows. Ask it to reuse the batch's fixed start dates, so the comparison is apples to apples.
  4. Record the verdict: “Log an experiment note: EMA20 improved mean Sharpe from 0.8 to 1.15 over the same ten windows.”
  5. Only then touch the deployed config — and that is a confirmation-gated action.

Recipe C — weekly slippage forensics

Show me every fill from the last thirty days where slippage was worse than ten basis points, grouped by symbol.Limit-order slippage is computed at insert time from filled_avg_price vs limit_price, so this is a straight query, not a guess.

Pattern to look for: one symbol consistently adverse → your limit is too aggressive for its spread. Fix the order type, not the strategy.

Recipe D — incident response, spoken

System ops — is everything green?Runs status: Postgres health, last snapshot per account, sync failures.
If anything is stale, tell me which account and when it last synced, and what you would check first.Forces a diagnosis instead of a status dump.

Recipe E — the quarterly autopsy

Which strategies in the journal have a negative expectancy over the last two hundred days, and what did I write about each of them at the time?Combines strategies with the vault — the ledger says what happened, the notes say what you thought.

09 · Prompt cookbook

Copy these verbatim, then adjust names and dates. Each one maps to a real tool action.

Telemetry

Sync all three paper accounts and tell me what changed since the last sync.sync then diff against the previous snapshot.
What is my total paper equity across all accounts right now?metrics, summed.
Which account has the worst ninety-day drawdown, and is it getting worse?metrics plus the equity series in os_account_snapshot.
Has any account gone more than a day without a sync?status — the staleness check that catches a silent scheduler failure.
Show me every fill this month and flag anything that filled worse than my limit.fills; the slippage sign is already adverse-positive.
Which strategy has the best expectancy per trade over the last ninety days, and on how many trades?strategies — sample size included, so a 3-trade fluke is visible.

Backtests

List the strategies I have changed this week.list, sorted by mtime.
Run ten windows on daily_golden_cross, ending last Friday, starting anywhere from 2015 to 2022.start with n_runs=10 — under the confirmation threshold, so it just runs.
Sweep daily_golden_cross with forty runs across 2018 to 2024.Crosses the 20-run threshold → the agent asks out loud before dispatching.
Poll that batch and tell me when the mean Sharpe crosses 1.2, or if it is going to miss.poll is a bounded wait — safe to ask repeatedly.
Which of my last fifteen batches had the best mean Sharpe, and what strategy was it?history.
Compare today's batch to the previous one using the same start dates, and tell me whether the change is real or noise.Reuses fixed_start_dates; the only comparison that means anything.

What did I change on this strategy last month, and what did I expect it to do?recent — returns the mutation notes with their diffs.
Turn today's findings into a note I can act on tomorrow: one experiment, one parameter, one date window.Forces specificity instead of a vague to-do list.

Operations

Check git status — is anything uncommitted before I deploy?git_status.

10 · Creative uses

1 · Pre-open brief at 08:45

Second cron, weekdays 08:45: positions, overnight gaps on holdings, anything reporting today (the DB already has earnings_calendar). Spoken, to your phone.

2 · Regime-aware expectancy

journal_trade carries regime_at_entry. Ask: “which regime does this strategy actually make money in?” — then stop trading it outside that regime.

3 · Mutation survival rate

Every mutation is logged with before/after. Quarterly: how many changes survived their first batch? A low survival rate means you are curve-fitting.

4 · Strategy graveyard

Retired strategies in journal_strategy plus their notes become a “what we learned” page. Cheaper than re-deriving the same dead end twice.

5 · Explain this trade

Pick a bad journal_trade row and ask @quant-dev to reconstruct the signal from the bars. The fastest lookahead-bias detector there is.

6 · Slippage budget

Track mean |slippage_bps| weekly. When it doubles, the strategy's edge is being eaten by execution, not ideas.

7 · Paper-to-live gate

Write the rule into the vault: “no deploy until three consecutive batches log Sharpe > 1.2 with the same windows.” Now the gate is auditable.

8 · Voice triage from anywhere

WhatsApp voice note → STT → “system ops, is everything green?” → spoken reply. The desk follows you.

9 · Two-strategy correlation check

Compare daily equity curves per account. If two strategies are the same bet in different clothes, the diversification is imaginary.

10 · Kill-criteria written in advance

Log, before deploying: “retire if drawdown exceeds 12% or expectancy goes negative over 40 trades.” Then let the daily loop watch it.

11 · Ask the vault, not the internet

“What did I conclude about the EMA10/200 prior last time?” — your own notes, via jarvis-tools search_vault, are the highest-signal context you own.

12 · One-number morning check

A single spoken sentence a day: total equity, day P&L, worst account. If it ever reads long, the system is failing, not the summary.

11 · SQL cookbook

Through sync_alpaca_telemetry action sql. Single SELECT or WITH only; anything containing INSERT, UPDATE, DELETE, DROP, CREATE, ALTER, TRUNCATE, GRANT, COPY is rejected before it reaches Postgres.

Equity, snapshot over snapshot

SELECT account_label, captured_at::date AS day, equity, day_pl
FROM os_account_snapshot
ORDER BY captured_at DESC
LIMIT 30;

Worst slippage by symbol

SELECT symbol, count(*) AS fills,
       round(avg(slippage_bps)::numeric, 2) AS avg_bps,
       round(max(abs(slippage_bps))::numeric, 2) AS worst_bps
FROM os_order_fill
WHERE slippage_bps IS NOT NULL AND filled_at > now() - interval '90 days'
GROUP BY symbol
ORDER BY avg_bps DESC NULLS LAST
LIMIT 15;

Expectancy by market regime

SELECT s.name AS strategy, t.regime_at_entry,
       count(*) AS trades,
       round(avg(t.pnl_pct)::numeric, 4) AS expectancy,
       round(avg(CASE WHEN t.pnl_pct > 0 THEN 1 ELSE 0 END)::numeric, 3) AS win_rate
FROM journal_trade t JOIN journal_strategy s ON s.id = t.strategy_id
WHERE t.exit_at IS NOT NULL AND t.regime_at_entry IS NOT NULL
GROUP BY 1, 2
HAVING count(*) >= 10
ORDER BY strategy, expectancy DESC;

Sync reliability

SELECT kind, status, count(*) AS runs, max(finished_at) AS last_finished,
       sum(rows_written) AS rows
FROM os_sync_run
WHERE started_at > now() - interval '30 days'
GROUP BY kind, status ORDER BY last_finished DESC;

What did the agent actually do?

SELECT acted_at, agent, action, status, left(detail, 120) AS detail
FROM os_agent_action
ORDER BY acted_at DESC LIMIT 25;

13 · Troubleshooting

SymptomCauseFix
Tools don't appear in a chat Tool schemas load at process start; no hot reload hermes gateway restart, then start a new chat. Check hermes plugins show aitrader_os → Status: enabled.
Bot profile has no tools Profiles are isolated ln -sfn ~/.hermes/plugins ~/.hermes/profiles/<name>/plugins
Every DB query: Permission denied tradecraft-db volume ownership flipped (uid 999 vs server uid 70) Stop container, chown -R 70:70 the volume from a root helper container, start it. Metadata only.
Replies are silent Edge TTS is blocked (HTTP 403) on this machine Provider is already macsay (macOS say). Check hermes config get tts.provider.
Spoken clip is half a second long A command template used {text}, which doesn't exist Use -f {input_path}; verify with ffprobe -show_entries format=duration.
“Hey Hermes” never fires Three causes, in order of likelihood: (1) capture: client — the Electron renderer must stream PCM, and it can silently send nothing; (2) confirmation_frames: 3 — the bundled model scores the bare phrase for only one frame, so it never satisfies three in a row; (3) mic permission denied for Hermes Use capture: local (the desktop backend is a child of Hermes.app, so it inherits the app's mic grant), confirmation_frames: 1, sensitivity: 0.5. Then restart the app and check ~/.hermes/logs/agent.log for listening (… external=False) — that proves local capture — followed by mic audio detected and phrase detected.
Wake arms, then stops every few minutes Each arm in capture: client mode that receives no frames is torn down and re-armed Same fix: switch to local capture. Say the phrase plus a few words (“Hey Hermes, what's my equity”) — a bare two-word phrase is marginal on a cold detector.
Cron ran, nothing arrived Job was created from a desktop session → save-only Re-point it: deliver='whatsapp' (or all).
BackendUnavailable on backtests uvicorn on :8000 isn't running The launchd job com.tradecraft.alpaca-backend should hold it up; check launchctl list | grep tradecraft.
Alpaca 401 / 403 Key rotation Update ALPACA_<n>_API_KEY / _SECRET_KEY in the repo .env — the plugin reads it live, no restart.
database "sp1500_1d" has no actual collation version Harmless startup notice Ignore it. Do not run REFRESH COLLATION VERSION — it can invalidate text indexes on 1,500 ticker tables.
