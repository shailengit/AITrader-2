Strategy Crafter

Natural Language → Verified, Reported Strategy

A multi-phase Claude Code skill that transforms a plain English trading idea into a verified, backtested, and beautifully reported strategy — ready for paper trading on Alpaca.

The Five Phases

Phase 1
Clarify & Coach
Claude engages you in a structured dialogue covering:
  • Entry signal design
  • Candidate ranking / scoring
  • Exit rules (priority order)
  • Position sizing strategy
  • Risk management (sector caps, volatility, bear mode)
  • Parameter tuning
  • Special filters
For each topic, Claude provides examples, critiques your choices, and recommends better alternatives.
💡 Tip: The more specific you are, the better the result. "Buy when RSI < 30 and volume > 1.5× average" is better than "buy oversold stocks".
Phase 2
Generate
Two files are created with identical logic:
  • strategies/<name>.py — standalone script, runnable independently
  • backend/app/services/strategies/<name>.py — Strategy ABC subclass for the app
Both use the same entry conditions, scoring, exit rules, and parameters.
⚠️ Critical: Both versions must produce identical performance. This is verified in Phase 3.
Phase 3
Verify
A 4-step verification suite:
  1. Syntax check (ast.parse)
  2. Standalone smoke test (short date range)
  3. In-app smoke test (via backtesting adapter)
  4. Identical performance check — both versions on the same date range
✅ Pass criteria: Non-zero trades, non-zero return, both versions within 0.1% return tolerance.
Phase 4
Learn (Interactive)
After running experiments in the app:
  1. Open the terminal (/terminal)
  2. Run claude to start Claude Code
  3. Share the HTML report path or describe performance
  4. Claude analyzes and suggests improvements
  5. You decide which changes to apply
💡 Tip: Run at least 10 backtest windows before the learning phase — more data = better improvement suggestions.

Example: Full Workflow

Here's what a complete session looks like:

USER
/strategy-crafter

I want a strategy that buys stocks when their 20-day EMA crosses above the 200-day EMA. Rank by how steep the crossover is. Hold 5 positions max. Exit when the death cross happens or after 60 days.
CLAUDE
Great idea! Let me ask a few questions to make this robust:

1. Scoring: You mentioned ranking by crossover steepness. What weight would you give the angle vs other factors like market cap? A 60/40 split (angle/market cap) is a common starting point.

2. Take profit: If a position goes up 30%, should we lock it in? Without take profit, winners can reverse.

3. Trailing stop: A 20% trailing stop from the peak protects against drawdowns. What do you think?

4. Bear market mode: Should we go to cash when SPY is below its 200-day SMA? This protects against major drawdowns.

5. Sector diversification: Max how many positions per sector? 2-3 is typical to avoid concentration.
USER
60/40 split sounds good. Yes to take profit at 30%. 20% trailing stop. Yes to bear market cash mode. Max 3 per sector.
CLAUDE
Good choices! One critique: a 20% trailing stop is reasonable, but with a 10% hard stop loss from entry price as a safety net during the first 7 days. Let me generate the code now...

Tips for Best Results

🎯 Be specific. "Buy when RSI(14) < 30 and volume > 1.5× 50-day average" generates a much better strategy than "buy oversold stocks with high volume".
📊 Know your exits. A strategy's exits matter more than its entries. Spend as much time on exit rules as entry signals.
🛡️ Add risk management. Sector caps, volatility filters, and bear market cash mode are what separate robust strategies from curve-fit ones.
🔁 Iterate. Run a batch, review the report, discuss improvements with Claude Code in the terminal, then re-run. Each iteration sharpens the strategy.
⚠️ Past performance ≠ future results. A strategy that backtests well may not forward-test well. Always paper trade before going live.
